# 定时下单工具 · Windows 源码分享包

适用 Windows 10/11，需安装 Python 3.12+ 和 Google Chrome。本项目包含源码、管理页面、依赖清单和模拟测试，不包含 Python、Chrome 或现成的运行环境。

## 从 GitHub 使用

下载本仓库的 ZIP 并解压，或使用 Git 克隆。运行 `setup.bat` 安装依赖，再运行 `start.bat` 打开管理页面。安装脚本会从 `config.example.yaml` 创建本机的 `config.yaml`；该文件及 `data/` 已被 Git 忽略。

以下分享包说明同样适用于源码使用。首次使用请用自己的账户登录并添加任务。

## 第一次使用

1. 将整个压缩包解压到固定目录，例如 `D:\jd-auto-order`，不要在压缩包内直接运行。
2. 安装 Python 3.12+（安装时勾选 Add Python to PATH）和 Google Chrome。
3. 双击 `setup.bat`，等待依赖安装结束。
4. 双击 `start.bat`，会打开 `http://127.0.0.1:8765/`。运行期间保持命令窗口打开。
5. 点击“扫码登录”，用自己的京东 App 扫码；随后“扫描购物车”选品，或点击“粘贴商品链接添加”创建详情页抢购任务。
6. 设置北京时间、数量及支付方式，先“演练到结算页”核对商品与金额，再按需启动任务。只有启用自动提交的任务才会提交订单。

分享包中的 `config.yaml` 和 `config.example.yaml` 均为空任务模板。需要在自己的电脑上重新登录、添加商品和设定时间；不会继承分享者的账户或任务。

## 复用普通 Chrome

管理页“京东使用的浏览器”可选独立模式或“复用当前 Chrome”。先停止旧任务，选择并保存复用方式；在管理页所在 Chrome（144+）的地址栏打开 `chrome://inspect/#remote-debugging`，开启允许远程调试。点击“检测浏览器连接”，由你在 Chrome 弹出的请求中允许。再在同一用户资料登录京东、保留一个购物车标签，扫描并演练。需要正常完成京东验证；复用不保证消除风控。

复用模式保留原登录会话和购物车标签，任务结束仅断开连接，保留浏览器及标签；无法连接时提示设置步骤，不另开独立浏览器。自动发现只读取 Chrome 的端口标记；不复制资料、导出 Cookie 或改写普通浏览器视窗与全局请求。多个购物车标签需要自行整理。默认分享配置仍为独立模式，朋友按需选择。

高级配置可设置 jd.browser_connection=existing、jd.cdp_endpoint=auto、jd.cdp_timeout_seconds=60。自定义资料目录用 jd.cdp_user_data_dir；显式端点仅允许本机 HTTP/WS。不要将个人目录和具体调试端点放入分享模板。淘宝/抖音继续使用原独立浏览器模式。

## 支付设置

默认使用京东结算页已有的支付方式。脚本不切换支付通道、不选银行卡、不选分期、不展开付款明细，也不再要求识别“不分期”或唯一信用卡方案；商品、数量、最终金额、订单提交位置、密码阶段和防重复提交仍会核对。仅支持在线支付；页面明确已选货到付款时停止，不擅自改动。

```yaml
jd:
  payment_preference:
    channel: default
```

保留旧任务升级时，旧 `auto`、`jd_pay`、`app` 及银行/卡号/分期偏好在新版中一律按页面默认处理，不会重新激活选卡逻辑。可将旧 `jd.payment_preference` 整块换成上面两行配置以清理多余字段；不要覆盖整个配置或清空任务。停止旧任务、关闭旧服务，将新版文件合并到原目录时保留自己的 config.yaml 和 data/，再用 start.bat 启动。若旧任务仍有 payment_method: cod，需改为 online。

结算按钮支持“分期付款 白条12期免息”等白条/信用卡免息文案，仍保留页面默认支付。新版摘要只显示商品总额和共减而未单列运费时，记录“未单列”，按最终应付核对，不推算为零运费。已列运费但读取失败或自定义必需运费选择器缺失时，仍停止/重试。

管理页的本次支付密码为可选项，不随分享包提供，不写入任务配置；重启购买任务后需要再次输入。提交前的密码验证与提交后的付款弹窗分别处理；不自动完成付款。

## 当前功能状态

- 京东：已实现持久登录、购物车扫描选品、定时调度、结算核对、自动提交及防重复提交。部分真实页面已检查，模拟流程已测试；实际自动下单成功尚未完整验证，页面变化仍可能需要适配。
- 京东购物车轮询：默认开售前 2 秒开始，每轮完成后间隔 200 毫秒，勾选与数量核对成功后停止刷新；晚于目标时间成功则立即继续结算。页面操作耗时另计，受任务截止时间约束。
- 京东商品详情页：无需扫描购物车，粘贴https://item.jd.com/数字SKU.html链接，设置数量和北京时间，保存后点击启动。名称可留空，链接中的SKU决定规格；启动即提前打开商品，前60秒检查登录、前30秒检查页面、前10秒核对数量与规格；预热最晚在前3秒结束，到点点击购买。无货或未开售按任务设置有界重试；沿用默认支付方式、保留手动付款。新入口已通过本地模拟流程测试，真实抢购成功未验证。旧管理进程需要关闭启动窗口、重新运行start.bat并刷新页面后才能加载该入口。
- 京东提前准备：启动购物车定时任务即打开购物车，前60秒复查登录、前30秒再次预加载。未开售时只读加载，不要求可勾选；空白或慢页面在准备阶段保持等待状态，短暂超时不会结束任务。单轮预加载最长15秒，可用 timing.cart_preload_timeout_seconds 调整；所有准备受轮询开始时间约束。开售前的慢轮询会在开售时刻结束等待并继续检查，已开始勾选同步时保留当前页面。订单基线查询最多等待5秒且不占用最后30秒的准备时间。
- 购物车关键路径：先处理其他商品和数量，最后勾选目标，只做一次批量核对，当前任务直接使用本次结果进入结算，不再重复全量核对。数量已正确时不重复定位或编辑。结算按钮可用即点击，暂不可用时保留选择，在原购买窗口内等待，不刷新购物车。页面导航或错误恢复后重新核对。已发起结算后等待当前页面完成；明确网络失败仍可有限恢复，真正混选其他商品仍会停止。
- 同账号多任务：同一时段最多一个购物车任务和一个详情页任务，各自结算。购物车勾选成功至本轮结算结束连续保留购物车通道锁，详情页使用独立通道。同路径任务的预热与购买窗口重叠时，启动前提示冲突。日志记录锁等待及勾选至结算的耗时；脚本持锁不等于锁定网站库存。
- 购物车控件等待：勾选与数量控件默认最多等300ms（timing.cart_action_timeout_ms），不沿用结算的5秒等待。导航在响应开始后直接检查真实正文和商品行，不额外等整页加载完成。日志记录刷新开始及慢步骤，事件记录各步骤耗时；200ms为每轮完成后的间隔，实际网络加载时间另计。
- 刷新等待优化：登录占位组件按50ms读取本地页面，账号出现即可继续，初次登录和明确登出仍要求状态稳定。账号标识批量读取，商品行等待直接返回批量快照，减少重复定位。事件增加body_ready（正文）和auth_ready（账号/验证）耗时；导航后的page_ready包含同一次正文和账号检查，复用页面或等待商品行期间的复查也累计到对应字段，不将字段简单相加。不改浏览器缓存或请求拦截，不保证网站响应速度。
- 购物车明确显示“待发布／等待抢购／尚未开售”等状态时，按未放货继续轮询，不在不可购买商品上等待勾选超时。勾选过程中变为不可买时允许下一轮刷新恢复。
- 淘宝：已有天猫商品页及部分结算结构适配；结算适配来自用户提供的页面代码截图和本地模拟。地址选中态、实际 SKU 证据、提交及结果等尚未完成验证，当前不能作为已可用的淘宝自动下单工具。
- 抖音：已有独立平台任务与调度框架，实际下单执行端尚未完成，当前不可自动下单。

未完成适配的平台保持不可启动；不要把模拟测试通过当作真实订单成功。临时人工验证需要在平台正常页面完成。

## 停止与重启

先在管理页点击“停止任务”，再在启动窗口按 Ctrl+C 关闭服务；重新双击 `start.bat` 后刷新页面。不要在旧购买进程仍存在时重复启动同一任务。

## 命令行检查

安装完成后，在项目目录中运行：

```powershell
.\.venv\Scripts\python.exe main.py check
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试使用本地模拟响应；测试通过不保证真实平台可正常结算。默认使用本地 Chrome，无须额外下载 Playwright Chromium。

## 文件与再次分享

压缩包含运行源码、测试、安装/启动脚本及 `MANIFEST.json` 文件校验清单。没有登录 Cookie、会话目录、真实任务、购物车记录、订单数据库、日志、截图、支付密码或本机开发记录。

开始使用后，个人数据会生成在 `data/`，真实任务保存在 `config.yaml`。再次分享时可运行 `python tools/package_source.py` 重新生成干净包，不要直接压缩已经使用过的整个目录。

## 购物车与详情页同时抢购

分别从购物车和商品链接添加任务，启用后在顶部选择“全部启用任务”，再启动定时任务。同一时段只启用一个购物车任务和一个详情页任务，两项任务独立计时、各用一个标签页分别结算，不合并商品。不要先单独启动一个任务再启动另一个，统一用顶部启动全部。

同一商品在重叠抢购窗口内只允许一路进入提交；另一路停止，提交结果未知时也不重复下单。不同商品可分别提交，支付仍沿用结算页默认选择，不自动付款。原有跨重启任务键防重继续保留。

2026-10-31已只读核对真实LG G6新版标题、规格、数量和购买入口，并加入脱敏模拟夹具；两种入口并发、最终提交和默认支付通过本地模拟验证，真实抢购成功尚未验证。旧版本正在运行的任务需先停止，再重新启动任务以加载新版代码；刷新管理页可看到使用说明。

### 一个购物车与一个详情页同时抢购

同一时段最多一个购物车任务、一个详情页任务，各自使用独立标签页和购买通道，分别生成订单，不合并商品。先保存两项任务，再从顶部选择“全部启用任务”启动。启用多项同路径任务时，预热到购买截止时间的窗口不能重叠；冲突会在启动前提示，不能悄悄合并或排队。每天任务也会检查后续日期及跨午夜冲突。立即演练按本轮同时执行检查，因此同路径最多一项。

同账号多购物车勾选会同步，多个详情页的京东内嵌结算也已实测串商品，所以不支持它们各自同时下单。一个购物车加一个详情页已通过本地并发模拟，包含普通结算及商品页内嵌结算；真实生成订单仍待验证。同一SKU跨入口仍只允许一次提交意图，结果未知时不会重复提交。

内嵌结算新增来源、名称规格、数量、推荐加购及最终应付核对；单个内嵌任务的付款拦截只转发浏览器原生生成的一次下单请求，接到响应后阻止本页继续付款，关闭脚本创建的商品页再移除拦截。不会构造私有下单请求或切换默认支付。该拦截当前仅通过本地模拟，尚未实单验证。

高级配置可选 `jd.run_budget: {max_total: 200, max_orders: 2}`，用于限制本次运行的合计提交金额和订单数，正常使用无需填写。已落盘的提交意图保留额度，结果未知时不返还。

### 2026-11-01：购物车结算跳转恢复

点击“去结算”后先确认本任务已进入订单结算页，并跟随该次点击产生的延迟新标签页。等待导航时保留原页面；超过等待期限仍停在购物车时，重新核对现有勾选和数量后有界重试，不主动刷新。已进入结算后又返回购物车时，也重新核对库存、勾选和数量，再发起结算；商品无货或混选时不继续。

结算字段只在实际结算页读取。读取期间退回购物车会明确报告页面变化，不继续在购物车等待运费或提交按钮。错误日志和截图旁的 JSON 记录脱敏站点、路径和结算状态，不记录查询参数。默认支付、金额核对、人工验证及订单防重规则继续生效。

上述导航失败、返回购物车及延迟弹窗恢复已加入本地模拟测试；尚未在真实抢购订单中验证。升级时保留自己的 config.yaml 和 data/，停止旧任务及管理服务后重新启动。

### 提交后首次提示留证

提交动作等待期间就观察已知缺货、拒单或验证提示；首次出现即写入日志及 `submit_feedback` 事件，并在查单前尝试保存 `submit-feedback` 截图。截图最多等待1.5秒，文本先保存，不再仅依赖数十秒后任务停止时的截图。`submit_click` 事件记录校准后的动作开始、结束时间；动作正常返回不等于订单已受理。查单未确认仍保留防重状态，不自动重发。此改动已加入本地模拟验证，真实拒单原因仍需当次证据。

### 2026-11-03：提示框恢复与可选自动付款

已识别的“多次提交过快”等提示框自动关闭；明确拒绝且确认关闭后，按任务的重试次数、间隔、截止时间在原结算页有限重试，后续逐步退避，不刷新购物车。未知弹窗或订单结果不明时仍先核实订单，付款开始后不会重复提交。

任务可勾选“自动付款（页面默认支付）”，或设置 `auto_pay: true`；分享模板默认关闭，需要接收者自行启用。开启后继续已识别的普通收银台和付款密码流程，沿用默认银行卡与分期，核对订单号及金额。密码只从管理页传入本次运行，不保存。付款结果不明不重复扣款；短信、指纹、人脸和扫码验证由用户正常完成，演练模式不付款。

商品页内嵌轻量结算的自动付款暂未适配，开启时会在提交前明确停止；可改用购物车或关闭该任务自动付款。付款与弹窗处理已通过本地模拟，尚未进行真实扣款验证，未知收银台需要继续适配。更换文件时保留自己的 config.yaml 和 data/，重启管理服务及任务后加载新界面。

### 2026-11-04：购物车勾选超时恢复

原生复选框在确认可见、可用和未被遮挡后使用空格键切换，避免布局稳定等待占满短超时。连续三次勾选失败后，先检查验证状态，再重新加载购物车恢复，不在同一页面一直空转。选中后仍停止刷新，已经开始结算或提交时不执行该恢复。改动通过本地模拟，真实开售效果待验证。
